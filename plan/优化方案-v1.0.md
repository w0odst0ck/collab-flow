## 二、P0 · 先做（低成本高收益，清欠账变钱）

### P0-1 模型路由验收（~10 分钟，offpeak）
- 验收 `cost-opt-model-gating` + `cost-opt-cache-dispatch`（卡 reviewed 3 天，工作区已干净 → 重跑 verify → accept）
- 价值：按任务类型/复杂度自动升降档，省 30%+ 成本

### P0-2 成本周报自动化（~1 脚本）
- 每周自动汇总：任务数 / 总成本 / 按项目 / 按执行器 / 按模型 / 峰谷节省
- 推送：飞书（个人/群，待定）
- 数据源：flow-cost-ledger + reasonix 日志 usage

### P0-3 预算上限告警（~1 脚本 + cron）
- 周/月预算阈值（config），超限 → 飞书告警 + 暂停新长任务
- 防成本失控

## 三、P1 · 中期（自动化核心升级）

### P1-1 任务树形分解（最大架构升级，独立 design）
- parent 任务 → 子任务树（design/execute/verify），可并行、依赖编排、自动聚合收口
- 现有线性链（chain-on-transition）→ 树形；钩子系统重新定位

### P1-2 本地模型档接入（含 think bug 修复）
- local 执行器修 think 流式解析 bug（NDJSON 907 行）→ 接入模型路由第三档
- 冷启动预热（keep_alive）→ fallback flash
- 价值：简单/整理/蒸馏任务零 API 成本

### P1-3 失败自愈增强
- timeout/failed 自动重试（次数/退避/降级 pro→flash 可配）
- 无人值守不卡死

### P1-4 自动验收闭环
- verify 过 → 自动 accept + 验收报告汇总

## 四、P2 · 增效深化

- 缓存感知排程：同仓同类任务自动串联（prefix cache 便宜 ~30 倍）
- 批量任务编排：模板化批量入队（batch 模板已有 5 个）
- 减债：script 执行器去留（本地档替代零成本需求后，script 可退役）、钩子链简化

## 五、细节优化清单（攒批）

### 成本核算细节
1. 峰谷节省字段：任务在空闲窗口跑 → 落账标注"原价 vs 实付"，周报可见省了多少
2. 缓存命中率追踪：prefix cache read 占比（reasonix 日志有 cacheRead）——缓存率高 = 成本低
3. 失败成本标注：重试/失败任务的花费单列，防"隐形浪费"
4. 成本单位统一：全部人民币（避免 $/¥ 混用）
5. 成本趋势：周/月环比（涨了要能定位到项目/执行器）

### 自动化细节
6. 子任务优先级继承：parent 优先级自动下传
7. 并发控制：同仓串行（cache-dispatch 雏形）+ 跨仓并行上限
8. 长任务进度可见：flowq 显示当前阶段（design/execute/verify）+ ETA
9. 超时自动降级：pro 超时 → flash 重试（省成本不卡死）
10. 幂等保障：重跑不重复花钱（result 缓存/去重）

### 模型路由细节
11. 本地档 fallback：qwen 不可用 → flash（降级链）
12. 档位规则可配：config 声明"任务类型 → 模型"映射
13. 输出 token 预算：max_tokens 控制（防长输出烧钱）

### 可靠性细节
14. 锁/并发冲突检测告警（已有部分，补告警通道）
15. 唤醒文本自包含（已有纪律，固化到模板）
16. 任务归档不删：可恢复（已有）
