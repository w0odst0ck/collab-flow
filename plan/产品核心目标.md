## 一、一句话定义

**collab-flow 是无人值守的自动化任务执行框架**：任务进来后，框架在后台自动分解为子任务、按任务类型挑选模型、遵守排程规则（峰谷/预算/优先级）自动执行、验证、收口。

**自动化**解决"人不在也能跑"，**成本核算**解决"跑得值不值"——两条腿，一个目的：**降本增效**。

---

## 二、三条核心目标（用户原话沉淀，2026-08-28）

### 目标 1：后台自动化处理任务

- 任务**后台自己跑**，无人值守推进：入队 → 自动执行 → 验证 → 收口
- **任务分解为子任务**：大任务 → 子任务树（设计/执行/验证分层，可并行、依赖编排、自动聚合收口）
- 失败自愈：timeout/failed 自动重试（策略可配），不卡死、不丢任务
- 唤醒/监控：pump 自动执行 + 异常告警 + 进度可见（flowq）

### 目标 2：按任务类型挑选模型（模型路由）

- 三档模型路由：**pro（深度思考）/ flash（性价比）/ 本地（零成本）**
  - design / verify / 复杂任务 → pro
  - execute / 常规任务 → flash
  - 简单/整理/蒸馏类 → **本地模型（ollama qwen，零 API 成本）**
- 按复杂度升降档（任务书规模/估算时长 → 升档降档）
- 缓存感知：同类任务连续跑，prefix cache 命中便宜 ~30 倍

### 目标 3：成本核算与规则约束（降本增效的度量）

- **每任务成本落账**：按执行器/模型/项目核算，成本可见可查
- **峰谷调度**：长任务锁空闲窗口（工作日夜间/周末），交互任务立即跑
- **预算控制**：周/月预算阈值，超限告警 + 暂停新长任务
- **成本周报**：每周自动汇总（任务数/成本/按项目/按模型/峰谷节省），推送可见

## 三、核心概念界定（防歧义）

| 概念 | 定义 | 现状 |
|---|---|---|
| **后台自动化** | 任务入队后无人值守推进（scheduled + pump + 唤醒） | ✅ 已实现核心 |
| **子任务分解** | parent → 子任务树（design/execute/verify，并行+依赖+聚合） | ⚠️ 当前是线性链（chain-on-transition），非树形 |
| **模型路由** | pro / flash / 本地 三档，按任务类型+复杂度选择 | ⚠️ 半成品：model-gating/cache-dispatch 未验收 |
| **成本核算** | 每任务 cost 落账 + 汇总 + 预算 + 周报 | ⚠️ 落账已有；汇总/预算/周报缺失 |
| **峰谷规则** | 高峰全价/空闲半价，长任务锁窗口 | ✅ 已实现（window.py + pricing.yaml） |
| **降本增效** | 自动化省人力 + 路由/缓存/峰谷省成本 | 北极星度量：任务吞吐↑、单位任务成本↓ |

## 四、当前基础盘点

## 五、非目标（明确不做）

- **不做分布式调度**：单机够用，多机是另一个产品
- **不做通用 CI/CD**：专注"LLM 任务执行"，不替代 Jenkins/GitHub Actions
- **不做复杂界面**：CLI + flowq 够，Web UI 按需再说
- **不做外部计费集成**：成本口径 = DeepSeek API + 本地零成本，只算自家账
