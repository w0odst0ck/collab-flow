# archive/ — 归档目录

> 归档规则：**已完成/废弃的历史产物**放这里，保留可恢复，不入活跃区。

## 内容

| 目录 | 内容 | 归档日期 | 恢复方式 |
|---|---|---|---|
| `2026-08-早期任务书/` | 任务书-P2 / P3 / 契约补丁（08-14/15 早期开发） | 2026-08-28 | `git log --all --oneline -- "任务书-P2.md"` 或 `git show <commit>:<路径>` |
| `plan-briefs/` | 6 个 workitem brief（与 .flow 本地 brief 相同；.flow 不入仓，此处是公开仓唯一存档） | 2026-08-28 | 同上 |

## 规则

1. **什么进 archive**：已完成任务的原始任务书/brief/旧文档——内容可能过时，但保留审计与恢复价值
2. **什么不进**：核心代码/测试/配置/当前文档（放活跃区）
3. **恢复**：git 历史 100% 保留（git mv / rename），需要时 `git show` 或直接复制回活跃区
4. **归档不删**：除非用户明确删除，archive/ 内容只增不减

---

*归档是"收起来"，不是"扔掉"——git 历史里都有。*
