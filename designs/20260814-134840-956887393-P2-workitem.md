## 1. work-item 目录与文件 schema

### 1.1 目录约定（相对项目根）

```
.flow/workitems/<id>/            # <id> 见 §1.2；框架工件最小单位，可整体 git 同步（P4）
  brief.md                        # 决策层产出（上下文包）
  design.md                       # 方案层产出（P3 由 designer 写）
  review.md                       # 审查意见（P3 由 critic 写）
  decision.yaml                   # 放行/打回/接管 + 缺陷清单（质量门输入）
  taskbook.md                     # 翻译层产出（P3 由 critic 翻译写）
  executor/
    result.json                   # 执行器结果清单（P3）
    diff.patch                    # 代码 diff（P3）
    cost.json                     # 执行成本（P3 可选）
    verify.json                   # 测试门机读结果（P2 新增 schema，P3 填真实值）
  verify.md                       # 测试门人类可读结论（P3）
  retro.jsonl                     # 复盘追加式记录（P5）
  status.yaml                     # 当前态 + 单写者锁（P2 核心，机读权威）
  events.jsonl                    # 追加式事件日志（P2 核心，审计/冲突消解）
  .lock                           # 本地互斥 sidecar（flock 用；不入 git）
```

- `new` 时**只创建**：目录 + `brief.md` + `status.yaml` + `events.jsonl`（首条 `create` 事件）。其余工件随阶段推进由相应命令/角色产出，**避免空工件歧义**（守卫以「存在且非空」判定）。
- `executor/` 由 `verify`（P2）或 `execute`（P3）按需创建。
- `.lock`、`*.tmp.*` 一律 gitignore（§7.2 说明 ignore 作用域）。

### 1.2 work-item id 规范

- 正则（硬编码于 `flow-core.py`，**不进 config**，规避 YAML 锚点/流式集合歧义）：`^[a-z0-9]+(-[a-z0-9]+)*$`，长度 1..64。
- 合法示例：`w1`、`fetch-data-guard`。
- 拒绝：大写、首尾 `-`、连续 `--`、`. / \`、`..`、空格、任意路径穿越特征。判定失败 → exit 2，绝不做路径拼接。

### 1.3 `status.yaml`（机读权威态 + 锁）

```yaml
schema_version: 1            # work-item schema 版本（P5 migrate 用）
id: fetch-data-guard         # 必须与目录名一致
state: created               # 受控词表：created|designed|reviewed|translated|executed|verified|accepted|retrospected
iteration: 0                 # 打回迭代轮数（feedback / verify_fail(design) 递增）
same_defect_count: 0         # 连续同类缺陷计数（reject 递增；类型变化或 pass 清零）
primary_defect_type: null    # 最近一次 reject 的主缺陷类型（受控词表 §5.3；pass 时 null）
takeover: false              # 是否已接管
re_execute_count: 0          # 实现问题重执行计数（verify_fail(impl) 递增）
process_version: 1.0.0       # 流程版本（P5 校验；P2 占位）
created_at: "2026-08-14T10:00:00+00:00"   # ISO8601 UTC（date +%FT%T%:z 口径）
updated_at: "2026-08-14T10:00:00+00:00"
event_seq: 1                 # events.jsonl 已追加事件数（= 末条 seq，冗余校验）
locked_by: null              # 单写者锁持有者（plane_id/角色 id；null=未锁）
lock_expires_at: null        # 锁过期时间 ISO8601 UTC；null=未锁
```

必填字段：上表全部（`primary_defect_type`/`process_version` 允许显式 `null`）。未知字段：读取时**忽略并告警**（向前兼容 P5 加字段）；`state` 非受控词表 → fail-closed（exit 2）。

### 1.4 `events.jsonl`（append-only 审计）

每行一个 JSON 对象，**只追加、不改写、不删除**；追加顺序即事件顺序。

```json
{"seq":1,"ts":"2026-08-14T10:00:00+00:00","event":"create","from":null,"to":"created","actor":"flow:control","guard":null,"reason":null,"meta":{}}
{"seq":2,"ts":"2026-08-14T10:00:05+00:00","event":"design","from":"created","to":"designed","actor":"flow:control","guard":"brief_required","reason":null,"meta":{"brief":"brief.md"}}
{"seq":3,"ts":"2026-08-14T10:00:09+00:00","event":"translate","from":"reviewed","to":"translated","actor":"flow:control","guard":"quality_pass","reason":null,"meta":{"verdict":"pass"}}
```

字段：`seq`(int，= 追加前行数+1，单调)、`ts`(ISO8601 UTC)、`event`(受控词表 §2.3)、`from`/`to`(状态或 null)、`actor`(默认 `flow:<plane_id>`)、`guard`(命中的守卫名或 null)、`reason`(拒绝原因码或 null)、`meta`(开放对象：守卫输入快照/verdict/锁信息)。红线：`meta` 写入前过 deny-list（拒绝 `sk-` 等疑似 secret 文本）。

### 1.5 `decision.yaml`（质量门输入，P2 由 `decision` 子命令或手工写）

```yaml
schema_version: 1
verdict: reject             # pass | reject | takeover（受控词表）
primary_defect_type: missing_scenario   # reject 时必填；受控词表 §5.3
defects:                   # 缺陷清单（list-of-mapping；reject 时非空）
  - type: missing_scenario
    detail: "未覆盖时区边界"
    caught_by: review
summary: "打回：补时区边界用例"   # 可选
reviewer: null             # critic 适配器 id（P3 填；零个人标识）
```

P2 只读 `verdict`（质量门）与 `primary_defect_type`（缺陷计数）。`defects` 为 **list-of-mapping** —— 这是 P2 新增解析器必须支持序列的原因（§1.7）。

### 1.6 `executor/verify.json`（测试门机读结果，P2 新增 schema）

```json
{"schema_version":1,"tests_pass":true,"diff_match":true,"error_table_match":true,
 "route":null,"checked_at":"2026-08-14T10:00:00+00:00","details":{}}
```

- 测试门**通过** ⇔ `tests_pass && diff_match && error_table_match` 全真。
- `route`：全真时 `null`；失败时必为 `design`（设计问题→回 designed）或 `impl`（实现问题→重执行），由 `verify` 子命令按 `--route` 写入。

### 1.7 YAML 子集解析器（`flow-core.py` 自带，自包含）

在 P1 受限解析器基础上**放宽到支持「映射 + list-of-mapping + 标量」**（P1 因决策层只需映射而刻意拒绝序列；P2 的 `decision.yaml.defects` 需要序列，故新增自包含解析器，**不改 P1**）：

- 支持：映射、`- key: value` 序列（仅限 mapping 元素）、`null/~`/`true`/`false`/int/float/`'单引号'`/`"双引号"`/裸字符串、`# 注释`。
- 拒绝（fail-closed）：锚点 `& *`、标签 `!!`、块标量 `| >`、流式集合 `{ } [ ]`、tab 缩进、重复键、文档指令 `%`/`---`/`...`。
- 序列化 `dump_yaml`：**键排序 + 确定性输出**（`key: value`、`null` 显式、按需引号），保证 git diff 稳定。

## 2. 状态机设计

### 2.1 状态与事件

状态（8，含 1 终态）：`created → designed → reviewed → translated → executed → verified → accepted → retrospected`。

事件（受控词表）：`create / design / review / translate / feedback / takeover / execute / verify / verify_fail / accept / retro`（另有非转移事件 `lock / unlock`，仅入日志不改状态）。

### 2.2 转移表（纯函数核心）

`transition(current_state, event, ctx) -> {"ok":true,"to":...,"guard":...,"effects":{...}} | {"ok":false,"reason":...,"detail":...}`

| # | event | from | to | 守卫名 | 守卫条件（ctx） | effects |
|---|---|---|---|---|---|---|
| 0 | create | ∅ | created | — | — | 计数器全 0，event_seq=1 |
| 1 | design | created | designed | `brief_required` | `brief_nonempty` | — |
| 2 | review | designed | reviewed | `design_required` | `design_nonempty && decision_present` | — |
| 3 | translate | reviewed | translated | `quality_pass` | `verdict=="pass"` | — |
| 4 | feedback | reviewed | designed | `quality_reject_retry` | `verdict=="reject" && same_defect_count < T` | `iteration+1`,`same_defect_count+1`,`primary_defect_type←decision` |
| 5 | takeover | reviewed | translated | `quality_reject_takeover` | `verdict=="reject" && same_defect_count >= T` | `takeover=true` |
| 6 | execute | translated | executed | `taskbook_required` | `taskbook_nonempty` | — |
| 7 | verify | executed | verified | `test_gate_pass` | `tests_pass && diff_match && error_table_match` | — |
| 8 | verify_fail | executed | designed | `test_gate_fail_design` | `NOT(全真) && route=="design"` | `iteration+1` |
| 9 | verify_fail | executed | executed | `test_gate_fail_impl` | `NOT(全真) && route=="impl"` | `re_execute_count+1` |
| 10 | accept | verified | accepted | `approve_confirmed` | `approve_confirmed` | — |
| 11 | retro | accepted | retrospected | — | — | 终态 |

- `T = gates.takeover_after_same_defect`（默认 2），可配置（§7.1）。
- `same_defect_count` 语义（对齐架构 §1.7「同类缺陷」）：feedback 时若 `primary_defect_type` 与上次相同则 +1，类型变化则置 1；`pass`/`takeover` 置 0。
- 事件 `verify_fail` 的目标由 `route` 决定（#8/#9 共用事件名），CLI 以 `<to>` + `--route` 消歧（§3.3）。

### 2.3 非法转移处理（拒绝原因码）

`transition()` 对非法输入返回结构化的 `reason` 码，CLI 映射到退出码（§3.4）：

| 原因码 | 含义 | 触发例 | exit |
|---|---|---|---|
| `unknown_event` | event 不在词表 | `foo` | 2 |
| `unknown_state` | current_state 非法 | `bogus` | 2 |
| `illegal_transition` | (from,event) 不在转移表 | created→accept | 2 |
| `guard_failed:<name>` | 转移形状合法但守卫不满足 | verdict=reject 时 translate | 1 |
| `bad_guard_input` | 守卫所需 ctx 字段缺失 | 无 `verdict` | 2 |

守卫失败**不产生任何状态变更、不追加成功事件**；仅在 `--dry-run` 下打印拒绝原因（§5.4）。

### 2.4 纯函数可测性保证

`transition()` 与 `evaluate_guard()` **零 I/O**：所有输入经 `ctx` 显式传入（verdict/计数/三条件/route/阈值），输出为新状态 + effects 或拒绝码。文件读取、锁、原子写全部在 store 层（§4），与纯函数隔离，使 §6.1 单测无需任何文件系统。

## 3. flow CLI 命令族

### 3.1 布局与总览

- `scripts/flow`（bash 薄壳）：`getopt` 解析 → 路径解析 → 分发 → `--json` 单行包装 → exit 透传（复用 dsh-design 的 `fail()`/`SCRIPT_DIR`/`readlink -f` 模式）。
- `scripts/flow-core.py`（python stdlib）：所有真实逻辑，子命令形式 `python3 flow-core.py <sub> ...`（对齐 `flow-config-core.py render` 模式），可被单测 `import` 纯函数。

```
flow --help
flow workitem new      <id> [--brief FILE] [--force] [--json]
flow workitem status   <id> [--json]
flow workitem transition <id> <to> [--event E] [--route design|impl] [--guard-check] [--force] [--json]
flow workitem list     [--state S] [--json]
flow workitem log      <id> [--limit N] [--json]
flow workitem lock     <id> [--owner ID] [--ttl SECONDS] [--json]
flow workitem unlock   <id> [--owner ID] [--force] [--json]
flow workitem show     <id> <artifact>          # 读任一工件（brief/design/status/...）
flow workitem guard    <id> --gate quality|test [--json]     # 守卫干跑（模拟验证）
flow workitem verify   <id> [--tests b] [--diff b] [--errors b] [--route design|impl] [--json]
flow workitem decision <id> --verdict pass|reject|takeover [--defect-type T] [--summary S] [--json]
```

未来命令族规划（P3–P5 占位，P2 不实现，仅登记命名空间）：`flow design <id>`、`flow review <id>`、`flow execute <id>`（P3 接适配器）、`flow sync`（P4）、`flow stats`、`flow retro <id>`、`flow process migrate`（P5）。

### 3.2 关键命令语义

- `new`：校验 id → 建目录 → 写 `brief.md`（`--brief` 复制内容，否则写空模板头）→ 写初始 `status.yaml`（state=created）→ 追加首条 `create` 事件（seq=1）。重复 id → exit 2，`--force` 覆盖重建。
- `status`：读 `status.yaml`，人读打印关键字段；`--json` 输出归一化对象。
- `transition`：见 §3.3。
- `list`：扫描 `.flow/workitems/*/status.yaml`，按 `updated_at` 降序；`--state` 过滤。
- `log`：顺序读 `events.jsonl`；人读为表格，`--json` 输出对象数组。
- `lock/unlock`：显式长时锁（§4.3）。
- `show`：`cat` 指定工件（`status.yaml` 走 YAML 重排输出；`.jsonl`/`.md` 原文）。
- `guard`/`verify`/`decision`：守卫框架 + 模拟验证（§5）。

### 3.3 `transition` 的 (from,to)→event 消歧

| (from,to) | 事件 | 消歧 |
|---|---|---|
| created→designed | design | 唯一 |
| designed→reviewed | review | 唯一 |
| reviewed→translated | translate / takeover | 读 `decision.yaml`：verdict==pass→translate；verdict==reject 且 count≥T→takeover；`--event` 可显式指定（守卫仍复核） |
| reviewed→designed | feedback | 唯一 |
| translated→executed | execute | 唯一 |
| executed→verified | verify | 唯一 |
| executed→designed | verify_fail | 需 `route==design`（读 `verify.json` 或 `--route`） |
| executed→executed | verify_fail | 需 `route==impl`（仅此 self-loop 合法） |
| verified→accepted | accept | `--approve` 置 `approve_confirmed`（§3.5） |
| accepted→retrospected | retro | 唯一 |

`--guard-check`：守卫**默认恒开**（fail-closed）；该 flag 保留为显式自述（流水线自文档化），不改变行为。`--force`：跳过守卫但**不跳过** (from,event) 形状合法性，事件 `meta.forced=true`，且**永不绕过锁**（红线：便利开关不削弱红线）。

### 3.4 退出码映射（沿用 0/1/2/124）

| 退出码 | 含义 | P2 触发 |
|---|---|---|
| 0 | 成功 | 正常 new/status/transition/list/log/lock/unlock/guard/verify/decision |
| 1 | 运行失败 | 守卫拒绝（`guard_failed:*`）、写盘失败、store 异常 |
| 2 | 用法或前置错误 | 参数缺失/非法 id/未知子命令/work-item 不存在/`illegal_transition`/`unknown_event`/锁被他人持有 |
| 124 | 超时 | P2 预留（store 全本地快操作）；P3 `execute` 透传 timeout |

`--json` 下所有错误经 stderr 输出单行 `{"status":"failed","error":"...","detail":"..."}`，stdout 保持可被 `jq`/`python -c` 消费的干净单行（复用 dsh-design `fail()` 模式）。

### 3.5 `--json` 输出契约（示例）

```json
// new
{"status":"ok","id":"w1","path":".flow/workitems/w1","state":"created"}
// status
{"id":"w1","state":"created","iteration":0,"same_defect_count":0,"takeover":false,"locked_by":null,"lock_expires_at":null,"event_seq":1,"updated_at":"..."}
// transition 成功
{"status":"ok","id":"w1","from":"created","to":"designed","event":"design","guard":"brief_required","event_seq":2}
// transition 守卫拒绝
{"status":"failed","id":"w1","from":"reviewed","to":"translated","error":"guard_failed:quality_pass","detail":"verdict=reject"}
// list
{"items":[{"id":"w1","state":"created","updated_at":"..."}]}
// log
{"id":"w1","events":[{"seq":1,"event":"create",...}]}
// lock
{"status":"ok","id":"w1","locked_by":"control","lock_expires_at":"..."}
// guard
{"id":"w1","gate":"quality","pass":false,"verdict":"reject","reason":"verdict != pass"}
```

## 4. store 层设计

> 分层：`store` 层负责全部 I/O；`transition()` 纯函数负责判定；`workitem` 子命令把两者串成「读 ctx → 纯判定 → 原子落盘」。

### 4.1 `status.yaml` 原子更新（temp + fsync + rename）

```python
def save_status_atomic(wi_dir: str, status: dict) -> None:
    tmp = os.path.join(wi_dir, f".status.yaml.tmp.{os.getpid()}.{secrets.token_hex(4)}")
    with open(tmp, "w", encoding="utf-8") as f:
        f.write(dump_yaml(status))          # 键排序、确定性输出
        f.flush()
        os.fsync(f.fileno())                 # 内容落盘，防 rename 后空文件
    os.replace(tmp, os.path.join(wi_dir, "status.yaml"))   # 同 fs 原子 rename
```

- 不变量：**读方永远看不到半写文件**（旧文件或新文件二选一）；异常路径 `finally` 清理 tmp。
- 单写者保证：`os.replace` 原子性 + 外层 work-item 级 flock（§4.3）共同保证。

### 4.2 `events.jsonl` 追加（flock，复用 manifest 模式）

```python
def append_event(wi_dir: str, record: dict) -> int:
    path = os.path.join(wi_dir, "events.jsonl")
    line = json.dumps(record, ensure_ascii=False) + "\n"
    lock_path = path + ".lock"
    fd = os.open(lock_path, os.O_CREAT | os.O_RDWR, 0o644)
    try:
        if hasattr(fcntl, "flock"):                       # POSIX：与 dsh-design manifest 同模式
            fcntl.flock(fd, fcntl.LOCK_EX)
        with open(path, "a", encoding="utf-8") as f:      # O_APPEND：无 flock 时也天然原子（单行 < PIPE_BUF）
            f.write(line)
            f.flush()
            os.fsync(f.fileno())
    finally:
        if hasattr(fcntl, "flock"):
            fcntl.flock(fd, fcntl.LOCK_UN)
        os.close(fd)
    return record["seq"]
```

- `seq` 由「追加前已有行数 + 1」计算（`events.jsonl` 为权威），`status.event_seq` 为冗余镜像，每次 transition 后校验相等，不等 → exit 1（自愈：以 events 为准重建镜像）。
- 降级：无 `fcntl`（非 POSIX）时退化为 O_APPEND 单行原子追加 + stderr 告警（对齐 dsh-design 的 flock 缺失回退）。

### 4.3 单写者锁（本地互斥 + 跨设备逻辑锁，双层）

**本地互斥（flock sidecar，串行化同一 work-item 的读-改-写）：**

```python
def with_workitem_lock(wi_dir, fn):
    fd = os.open(os.path.join(wi_dir, ".lock"), os.O_CREAT | os.O_RDWR, 0o644)
    fcntl.flock(fd, fcntl.LOCK_EX)
    try:
        return fn()                 # 在锁内完成：读 status → 判锁 → transition → 写 status → append event
    finally:
        fcntl.flock(fd, fcntl.LOCK_UN); os.close(fd)
```

**跨设备逻辑锁（`status.yaml` 字段，P4 git 同步的冲突消解依据）：**

```python
def acquire_lock(wi_dir, owner, ttl_s, now):
    def _do():
        s = load_status(wi_dir)
        if s["locked_by"] and not is_expired(s, now):
            raise Locked(s["locked_by"])              # 他人持有且未过期 → exit 2
        s["locked_by"] = owner                        # 过期锁自动视为空闲并覆盖
        s["lock_expires_at"] = now + ttl_s            # ISO8601 UTC
        save_status_atomic(wi_dir, s)
        append_event(wi_dir, event("lock", meta={"owner": owner, "ttl_s": ttl_s}))
    return with_workitem_lock(wi_dir, _do)

def is_expired(s, now):                               # 过期自动释放
    exp = s.get("lock_expires_at")
    return exp is None or parse_iso(exp) <= now
```

- `transition` 在锁内**隐式短锁**：先判逻辑锁（他人持有且未过期 → 拒绝），应用转移，随后清 `locked_by/lock_expires_at`（释放）。
- 显式长锁（`lock` 子命令）供「某角色占用整阶段」场景；`unlock` 校验 `owner` 匹配，`--force` 可强制清（记录事件）。
- 锁 TTL 默认 `workitem.lock_ttl_s`（3600s）；`lock --ttl` 覆盖。
- owner 默认 `flow:<plane_id>`（`plane_id` 来自 config，默认 `control`），**绝不取 hostname/用户**（零个人标识）。

```python
def build_ctx(wi_dir, event, overrides):
    c = {"takeover_after_same_defect": cfg.gates.takeover_after_same_defect}
    if event in ("review","translate","feedback","takeover"):
        d = read_decision(wi_dir)                    # decision.yaml
        c["verdict"] = d.get("verdict")
        c["decision_present"] = file_nonempty(decision.yaml)
        c["same_defect_count"] = load_status(wi_dir)["same_defect_count"]
    if event in ("verify","verify_fail"):
        v = read_verify(wi_dir)                      # executor/verify.json
        c.update(tests_pass=v.tests_pass, diff_match=v.diff_match,
                 error_table_match=v.error_table_match, route=v.route)
    if event in ("design",):      c["brief_nonempty"] = file_nonempty(brief.md)
    if event == "review":         c["design_nonempty"] = file_nonempty(design.md)
    if event == "execute":        c["taskbook_nonempty"] = file_nonempty(taskbook.md)
    c.update(overrides)                              # CLI --route/--approve 覆盖
    return c
```

### 5.3 模拟验证（P2 不接真实执行器，P3 替换生产方）

- `flow workitem decision <id> --verdict pass|reject|takeover [--defect-type T]`：写 `decision.yaml`（schema §1.5），是 **critic 适配器的 P2 替身**。`--defect-type` 取受控词表：`constraint_violation / missing_scenario / untestable_acceptance / out_of_scope / untranslatable`（设计层，对齐架构 §3.1）。
