# 审查清单（critic 环节）

> 用法：审查 design 方案时逐项核对；任一关键项不过 → 打回 designer 迭代

## 方案审查（设计层）

- [ ] **目标对齐**：方案是否回应真实目标，不跑偏、不夹带私货
- [ ] **约束遵守**：技术约束/红线是否被尊重；**范围外想法单独记录，不混进方案**
- [ ] **风险识别**：风险与缓解是否全面、可信
- [ ] **验收可测**：验收标准是否可执行验证（不空泛）
- [ ] **遗漏场景**：边界情况、失败路径是否覆盖（off-by-one/时区/空输入/脏数据）
- [ ] **测试策略**：验证手段明确，测试用例可落地

## 翻译审查（方案 → 任务书）

- [ ] **翻译校验**：能否改写成无歧义任务书（不能 = 打回 designer）
- [ ] **错误处理表核对**：方案的**每个错误场景** → 任务书/实现有对应处理 → 测试有用例覆盖
- [ ] **自查提示注入**：任务书含 bash 自查提示与 0 值/权限检查项

## 执行验收（实现后）

- [ ] **测试全过**：测试用例全绿
- [ ] **diff 对照方案**：实现与方案逐条核对，不盲信执行器自报
- [ ] **可执行权限**：所有脚本 chmod +x
- [ ] **0 值字段**：数值 0 不被 falsy 判断吞掉（is not None 而非 or ""）

## 红线审计

- [ ] **便利开关不削弱红线**：--skip 类开关只跳过非红线环节；红线校验（模型回验/权限/key）在任何开关下生效，缺失时显式告警而非静默放行
- [ ] key 安全：不落盘/不打印/日志过滤（redact 管道化，无 python3 时输出占位符不回退原文）
- [ ] 工作区隔离：只写设计目录，不碰生产代码

## 审查产出物（物化）

1. 判定：通过 / 打回（附理由）/ 接管
2. 缺陷清单：类型（约束违反/遗漏场景/验收不可测/红线）——记入复盘数据
3. 修正指引：喂回 designer 的批评意见（同类缺陷 2 次 → 接管）
4. 翻译产物：executor 任务书
