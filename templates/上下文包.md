# 上下文包模板（designer 输入）

> 用途：critic（决策层）写给 designer 的任务简报
> 原则：**不含答案**（不泄露预期解法），只给背景/目标/约束/红线/验收——让 designer 自己发现边界

---

【任务：<标题>】

【背景】
<为什么做；上下游上下文；已知问题场景；相关代码/接口事实>

【目标】
<做什么；成功长什么样；明确不做的事>

【约束】
- <技术栈/版本/现有实现约束>
- <必须保持的兼容性/结构>
- <可测试性要求>

【红线】
- <禁止改动的模块/文件>
- <数据安全边界>
- <行为边界（如：只产出方案不执行）>

【验收标准】
请输出完整方案设计，包含：
1. 方案设计：数据流 / 判定逻辑（含伪代码）/ 边界处理
2. 测试策略：具体测试用例设计（含边界用例）
3. 风险识别：风险与缓解措施
4. 你的方案为什么能防住「<核心问题一句话>」

---

## 质量检查（critic 写完后自查）

- [ ] 背景是否给足 designer 独立判断所需事实
- [ ] 是否意外泄露了答案
- [ ] 红线是否覆盖数据安全/范围边界
- [ ] 验收标准是否要求「防住核心问题」的论证
- [ ] 模板复用（稳定前缀 → cache 命中 → 降本）
